# Contributing

Спасибо за интерес к проекту. Сначала обсудите значительные изменения в issue, если это возможно; соблюдайте существующие ограничения синтетических данных и не добавляйте секреты.

## Подготовка

Нужны Python 3.12, [uv](https://docs.astral.sh/uv/) и Docker Compose. Из корня репозитория:

```sh
uv sync --locked
cp .env.example .env
# Задайте собственный локальный POSTGRES_PASSWORD в .env.
docker compose up --build -d --wait
```

В PowerShell используйте `Copy-Item .env.example .env`. Инструкции запуска и demo — в [README](README.md#quickstart) и [docs/demo.md](docs/demo.md). Файл `.env` не должен попадать в Git; Telegram оставляйте выключенным при тестировании.

## Проверки

```sh
uv run ruff check .
uv run ruff format --check .
uv run pytest
```

Для интеграционных тестов установите `TEST_DATABASE_URL` на **отдельную тестовую PostgreSQL-базу**. Тесты удаляют схемы `raw` и `analytics` в этой базе. Имя должно содержать отдельный сегмент `test`, например `marketplace_test`; одного имени недостаточно для гарантии изоляции. Без переменной эти тесты пропускаются. Проверку `dbt build` можно запустить через `marketplace_job` после загрузки данных. CI также проверяет контейнерный запуск.

Форматируйте Python командой `uv run ruff format .`; не добавляйте зависимость без обоснования. Описывайте ограничения и проверяйте документацию вместе с изменениями поведения.

## Pull request

Работайте в отдельной ветке, объясните назначение изменения, перечислите выполненные проверки и известные ограничения. Не включайте реальные данные клиентов, credentials, `.env` или dumps. Не отправляйте настоящие Telegram-сообщения без согласия получателя. Проект пока не содержит файла лицензии; условия повторного использования определяет автор.
